## 2. 시스템 개요
- 현장 사진과 제품 정보를 받아 AI(Gemini)가 티링크 제품의 기술 차별점을 분석하고, 홍보 제목·블로그·SNS·카드뉴스를 생성한다. 근거는 지식베이스 ID(F001~F010, K001~K014)로만 표시한다.
- 고객 전달: PDF 브로셔 미리보기·다운로드, Word·PPT·Excel 변환, ZIP 일괄 다운로드, SMTP 이메일 발송
- DB: SQLite(`studio/.data/tlink.db`)에 생성·수신 고객·발송·내보내기 이력을 저장한다. PostgreSQL은 저장소 인터페이스만 준비했다(ADR-0002).
- 관리 화면: `/admin`(AI 모델 관리), `/history`(메일 발송 이력, 콘텐츠 생성 이력, 수신 고객, 내보내기 이력). 둘 다 `ADMIN_TOKEN`이 필요하다.

## 3. 설치·실행 절차 (새 PC 기준)
1. Node.js를 설치한다(검증 환경 v26.13.1). DB에 내장 `node:sqlite`를 쓰므로 플래그 없이 쓸 수 있는 22.13 이상(또는 23.4 이상)이 필요하다. 인수인계 테스트에서 실제로 확인한 버전은 7절에 기록한다.
2. `git clone` 후 `cd studio`, `npm ci`
3. `.env.local.example`을 복사해 `.env.local`을 만들고 값을 채운다(4절).
4. `npm run build`, `npm start`. **반드시 `studio` 폴더에서 실행한다**(DB 마이그레이션 경로).
5. http://localhost:3000 접속 → README 5절 시연 절차대로 확인한다.

## 4. 비밀정보·환경변수 (값은 이 문서에 기록하지 않는다)
| 변수 | 용도 | 관리 주체·주의 |
|---|---|---|
| `GEMINI_API_KEY` | AI 생성(필수) | Google AI Studio에서 발급. 사용량과 과금을 확인한다 |
| `OPENAI_API_KEY` | 예비 모델(현재 비활성) | 향후 추가 시 `/admin`에서 활성화 |
| `ADMIN_TOKEN` | `/admin`, `/history`, 이력 API 접근 | 긴 무작위 문자열을 쓰고 담당자만 공유한다 |
| `SMTP_HOST/PORT/SECURE/USER/PASS`, `MAIL_FROM` | 이메일 발송 | Gmail은 2단계 인증 + 16자리 앱 비밀번호. **계정 비밀번호를 바꾸면 앱 비밀번호가 무효가 되므로 다시 발급한다** |
| `DATABASE_URL` | DB 위치(기본 `sqlite:./.data/tlink.db`) | PostgreSQL은 미구현(오류 발생) |

## 5. 운영 체크리스트
- **개인정보**: `studio/.data/`에는 수신 고객 정보와 원본 현장 사진이 저장된다. 접근 권한을 통제하고 정기적으로 백업한다(서버를 멈추거나 WAL 체크포인트 후 파일 복사). git에는 올라가지 않는다.
- **메일 발송 한도**: IP당 분당 3회, 서버 전체 시간당 30회. 메모리 기반이라 재시작하면 초기화된다. Gmail 자체 일일 한도도 별도로 있다.
- **AI 결과 확인**: AI 생성 결과는 게시 전에 담당자가 사실 여부를 확인한다(화면 하단 고지).
- **모델 교체**: Gemini 모델 ID가 폐기되면 `/admin`에서 새 모델을 추가해 기본으로 지정하고 [연결 테스트]로 확인한다.
- **보안 조치(즉시)**: 개발 중 대화에 노출된 메일 계정 비밀번호는 변경해야 한다. 변경 후 앱 비밀번호를 다시 발급해 `.env.local`에 반영한다.

## 6. 알려진 제약과 후속 과제
| ID | 내용 | 권장 |
|---|---|---|
| K-01 | OpenAI 예비 모델은 실제 호출을 검증하지 않았다(범위 제외, PRD C5) | 키 발급 후 시험 |
| K-02 | PostgreSQL 어댑터 미구현 | `src/lib/db/postgres.ts` 추가(ADR-0002) |
| K-03 | AI 모델 설정은 아직 JSON 파일(`config/ai-models.json`)에 저장한다 | DB로 이전 |
| K-04 | 90초 타임아웃이 실제로 발생하는 경로는 미검증 | 부하 시험 |
| K-05 | 메일 속도 제한이 메모리 기반이다 | 다중 서버 시 공용 저장소 |
| K-06 | 시연 녹화 스크립트(`시연영상/스크립트/`)는 개인정보가 포함되어 git에서 제외했다 | 재녹화 시 로컬에서 수신자 값을 바꿔 사용 |
| K-07 | 제공자료 대용량 파일(회사소개서 PDF 237MB, 쇼릴 25MB 등)이 git 이력에 포함되어 clone이 느리다. 이력 재작성은 파괴적 작업이라 하지 않았다 | 신규 대용량 파일은 Git LFS 또는 저장소 밖(드라이브)에 보관 |
