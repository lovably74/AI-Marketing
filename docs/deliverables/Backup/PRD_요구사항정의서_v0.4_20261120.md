## 1. 배경과 목표

### 1.1 원래 과제 (변경 불가)
> "티링크의 제품과 기술적 차별점을 AI가 분석하고, 현장 사진과 제품 정보만으로 고객의 관심을 끌 수 있는 홍보 콘텐츠를 자동 생성하는 마케팅 솔루션을 개발해 주세요."

### 1.2 핵심 목표 (P0)
| ID | 목표 |
|---|---|
| G1 | AI가 티링크 제품과 기술적 차별점을 **실제로** 분석한다 (고정 문구·사전 결과 금지). |
| G2 | **현장 사진 1장 + 제품 정보**만으로 분석을 시작할 수 있다. |
| G3 | 분석 결과를 근거로 고객 관심을 끄는 홍보 콘텐츠(제목·블로그·SNS·카드뉴스)를 자동 생성한다. |

### 1.3 성공 기준 (완료 기준 — 원 과제 12절)
사진 업로드 → 제품 정보 입력 → 생성 버튼 → **실제 AI API** 차별점 분석 → 편익·근거 표시 → 제목 3종 → 블로그·SNS → 사진 기반 카드뉴스 → 문구 복사 → 카드뉴스 PNG(1080×1080) 다운로드, 그리고 `npm run build` 성공.
API 키가 없거나 실제 호출을 검증하지 못한 항목은 "완료"로 보고하지 않는다.

## 3. 범위

### 3.1 포함
입력 화면, `POST /api/generate`, 결과 화면(A 분석 / B 콘텐츠 / C 카드뉴스), PNG 다운로드, 텍스트 복사, 지식베이스 JSON, 모델 관리 페이지와 API, README 시연 절차.

### 3.2 제외 (원 과제 11절 유지)
회원가입·로그인, DB, 벡터검색·RAG, PDF·PPT 실시간 분석, 실시간 경쟁사 검색, 외부 CRM 연동, SNS 자동 게시, 동영상 생성, 결제, 다중 카드뉴스, 복잡한 관리자 화면(C2의 단순 모델 관리는 예외).

## 5. 지식베이스 (data/tlink-knowledge.json)

근거 문서는 [현업무분석서_제공자료분석.md](현업무분석서_제공자료분석.md)이다. 10개 기능 모두 제공자료에서 "명확" 근거를 확인했다.

### 5.1 구조
```json
{
  "product": "티링크 비즈레코딩", "brand": "T-LINK", "company": "㈜티링크앤주인닷컴",
  "features": [ { "id": "F001", "feature": "", "description": "", "benefit": "", "source": "" } ],
  "facts":    [ { "id": "K001", "fact": "", "source": "", "caution": "" } ],
  "cautions": [ "콘텐츠 작성 시 주의사항" ]
}
```
- `features`: 원 과제의 기능 10개(F001~F010). 형식은 원 과제 3절을 따른다.
- `facts`: 기능 외에 자료에서 확인된 차별점(K001~). 예: LG·SK·KT 회선 호환, 99% 녹취 성공률, 1,000+ 도입 기업, 실시간 통역 60개 이상 언어, PC 소프트폰 지원 OS 등.
- AI의 `evidence`는 `features`·`facts`의 ID 또는 `USER_INPUT`만 허용한다(FR-API-06).

| ID | 기능 | 주요 출처 | 주의 |
|---|---|---|---|
| F001 | 휴대폰·인터넷전화·PC 소프트폰 통화 이력 통합 | 제안서 S1·S3, CRM매뉴얼 28p, 회사소개서 7p | PC폰 녹음은 삼성 070 계정에서만 가능(PC폰매뉴얼 16p) |

| F003 | STT 문자변환 | CRM매뉴얼 14~15p, PC폰매뉴얼 12p, 제안서 S4 | 실시간 STT는 계정 설정에 따라 제한 가능 |

### 6.1 그대로 적용하는 규칙
| 구분 | 내용 | 검증 방법 |

### 6.2 원 과제와 충돌하거나 근거가 없어 조정한 규칙 (PM 결정)
| 가이드라인 원문 | 조정 내용 | 사유 |
|---|---|---|
| 미션 8: "실제 사용 후기 형식" | **"도입 검토 가이드형" 소개글**로 쓴다. 1인칭 체험 주장("직접 써 보니", "우리 회사에 도입해 보니")은 금지하고, "통화가 끝나면 이런 흐름으로 기록됩니다"처럼 기능 흐름을 설명한다. | 원 과제 "허위 사용 후기 금지"가 우선 |
| 추천 구성 ⑤: "…만족스러워 합니다" | 고객 만족 인용은 쓰지 않는다. | 확인되지 않은 고객 반응(허위 후기 위험) |
| 미션 11: "AES256·SHA256 암호화" | **AES256만** 언급한다. | SHA256은 제품 자료에 근거 없음 |
| 미션 6: "고객 이탈 위험" | 쓰지 않는다. 대신 RED 알림(같은 이슈 3회 반복 시 긴급 리스크 경보)·VOC 이슈 자동 분류로 표현한다. | 근거 없음 |
| 서브 키워드·태그: "회의록작성" | 쓰지 않는다. | 근거 없음 |
| 미션 2: "집에서는 PC폰으로 동시에 자동 녹음" | PC 소프트폰 통화 이력 통합은 언급하되 녹음은 "삼성 070 계정에서 지원" 같은 단서 없이 단정하지 않는다. | PC폰매뉴얼 16p 제약 |
| 미션 3: "고객 요청사항과 후속 조치가 자동 기록" | 통화별로는 한줄요약·키워드·화자별 대화가 자동 기록되고, 후속조치는 종합리포트의 영업기회 표·미결 추적으로 표현한다. | 근거 범위 |
| 미션 9: 화면 이미지 5종 순서 배치 | 본문에 `[이미지: 휴대폰 통화 화면]` 같은 **삽입 위치 표시**만 넣는다(이미지 생성·첨부는 하지 않음). | 이미지 생성 AI 미사용 |

### 6.3 금지 사항 (서버 검증 대상)
- 1인칭 허위 체험·후기 표현, 확인되지 않은 고객 만족·도입 효과 인용
- 비교자료 없이 경쟁사 대비 절대 우위 주장("업계 최초", "유일", "1위", "최고", "최적의 대안·솔루션" 등)
- 고객사 예시 화면 수치(115건, 6건, 9개, 78점 등)를 일반 성과처럼 쓰는 것
- 요금 언급(예시 견적이므로 콘텐츠에서 제외)
- 회사소개서의 대표 개인 연락처(휴대전화·개인 이메일) 사용
- 공식 연락처 외의 전화번호 생성

서버는 금지 표현 패턴을 검사해 `guidelineCheck.warnings`로 결과 화면에 표시한다. 수치는 지식베이스에 있는 값만 허용한다.
